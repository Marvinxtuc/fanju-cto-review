# U1 用户订单找回契约

本地实现已落地，自动化/构建验证中，未作设备或上线验收。目标F19/F20与T22：用户登录后从服务器找回自己的全部历史订单，按订单ID查看状态、继续支付或提出取消；不依赖本地lastOrderId，不将requestPayment回调当作服务器已收款。复用A2资金接口，L1未通过时如实显示到期/资金核查中的限制。

## API增量

- GET /api/orders：requireUser；只查当前userId。createdAt/id倒序，返回最多20条及nextCursor；游标必须能在本人订单集合中找到，不能跨用户探测。摘要只有订单ID、状态、金额、创建时间、活动ID/标题/开始结束时间；不包含问卷、openid、手机号、渠道凭证或未解锁餐厅地址。
- GET /api/orders/:id：保留现有权限/地址解锁检查；增加足够的本人退款进度摘要（ID、状态、金额、更新时间）及可操作状态。资金UNKNOWN/MANUAL需明确处理中/待核查，不暴露内部case内容。
- POST /api/mock/payments：保留兼容路径。按当前订单ID续付，接受A2的processing/requiresReview/payable字段；无paymentParams且非显式演示mock时不得模拟成功。
- POST /api/orders/:id/cancel：已支付取消走既有退款申请，受理不等于已退钱；待付到期/取消依赖L1，未实现时不伪装成功。

## 小程序

新增我的订单列表页：首页有入口，登录后从服务端刷新；清缓存/重新进入仍能找回。详情显式读取路由orderId，兼容旧lastOrderId仅作为导航提示，不能作为唯一数据源。

详情显示中文业务状态、退款进度、刷新按钮；待付且允许续付时可再次支付，用户取消微信收银台保留订单并提示可继续；成功返回后刷新服务端订单，未收敛显示处理中。申请取消需要理由、按钮防重复提交，成功后刷新真实退款状态。

登录过期清除本人页面中的旧数据并进入重新登录路径；页面切换、旧请求迟到不能覆盖新选订单或新账号数据。列表分页不能泄露另一账户订单。业务文案保持餐厅兴趣体验定位。

## 验收

- 两个用户订单互不可见；外部/伪造游标、他人订单ID拒绝。
- 超过20条历史订单可分页；无重复或漏页，当前页最多20条。
- 清本地订单缓存后仍可从服务器列表打开订单。
- 路由订单A与本地缓存B冲突时显示A；切换账号/详情后旧请求不覆盖。
- 续付取消/失败保留订单；MANUAL无支付参数不调用requestPayment或mock succeed；服务端未确认不得显示已付款。
- 退款申请受理显示审核/处理中，不能显示已退款。
- 真实API/PG测试、小程序契约测试、类型检查、真实weapp构建；设备和微信IDE体验另列未执行，不用编译替代。
