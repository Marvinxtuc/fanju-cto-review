# O1 本地运营流程实施记录

更新于 2026-09-30。用户已批准 O1 本地实施。本报告仅记录隔离工作副本与可丢弃 PostgreSQL 的结果；不代表 G3 或上线签收。

## 交付范围

- 运营台可以创建、编辑餐厅，创建活动草稿、发布并开放报名。活动创建校验报名截止、开始与结束时间顺序，人数和容量关系，以及餐厅状态与容量。已有排期时，餐厅位置与容量不能直接改写。创建、编辑、发布和开放报名均写审计；审计不记录联系人或电话。
- 已有的成团、排桌、运营取消、履约和退款审核接口接入页面；新增黑名单解除按钮和资金异常待办认领、证据复核结案入口。待办结案只接受已存在的终态证据，要求具名管理员认领且由另一名超级管理员复核；不直接修改资金事实。
- 运营列表提供稳定游标与总数，页面沿游标取完当前记录；活动的已占席位来自 `Order.capacityHeld` 聚合，订单同时展示实际收款笔数、实收合计和关联未结异常数。正式容量增长时，页面应改为按需加载，避免一次拉取全量记录。
- 跨源管理请求使用 `OPS_ALLOWED_ORIGINS` 精确白名单；本地默认允许 5173 开发源，生产配置为空时只接受同源页面。解除黑名单的 `DELETE` 已纳入预检方法。页面按登录角色隐藏超级管理员专属动作，API 仍执行独立授权。
- 举报从 `OPEN` 到处理结果使用条件更新，并发请求至多一个成功、一个审计记录。

## 尚未通过的门禁

- 浏览器链路使用本地演示管理员和 mock 用户，尚未以受控本地账号完成同样的空库操作。退款渠道确认、用户报名和提交反馈由可丢弃环境中的测试夹具完成；真实小程序和渠道联调未执行。资金异常待办的受控结案仅经过 API 负面路径测试，尚无真实终态证据的浏览器正向样例。并发审批与异常收款关联仍以数据库/API 路径为证据。
- 正式餐厅资料、协议文本、正式运营域名及其 CORS 来源、微信身份/支付/退款联调、迁移兼容回退、备份恢复、部署签收和真实收费均未在本次验证。G0–G4 不因本报告自动改变状态。
