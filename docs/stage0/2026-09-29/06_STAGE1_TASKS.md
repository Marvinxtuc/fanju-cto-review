## S1a 最小安全隔离：先拒绝无凭证后台

对象：`services/api/src/app.ts`、`providers.ts`、拟新增 `config.ts` 与 security 测试；运营端错误提示按需最小更新。不得整段封 `/api/mock`：其中登录、手机号、支付创建实际承载真实 provider。

推荐具体行为：

- 显式本地演示模式才注册 `/api/mock/admin-login`、支付 succeed、退款 succeed/fail；非本地模式不注册。默认生产禁止，环境组合不合法启动失败。
- 真实身份与资金创建既有路径暂保留兼容，验证逻辑不降级；新规范路径若需要新增，单列契约批准。
- 在尚无可信管理员认证时，生产全部 ops 写/读接口拒绝演示凭证，不以演示管理员临时上线。
- 不能仅隐藏前端按钮；操作权限由服务端决定。任何未授权 role 输入不得修改账号角色。

验收：生产模拟入口 404、无凭证不能得到 token、伪造 role 不更新 DB、真实身份兼容入口保留；现有隔离测试显式声明演示模式，不能删除权限断言换绿灯。F01/F03 的正式安全用例需覆盖 NODE_ENV/配置矩阵，而非仅本轮默认测试环境的复现。

回退：停止后台写服务或切安全兼容版本；不能恢复公网演示赋权。无生产部署/防火墙操作在此本地代码包内。

## S1b 会话基准与旧 token 处理

对象：`auth.ts`、签发点、用户/运营 API 401/403 处理。新账号状态/sessionVersion 字段另附迁移评审，不混入 S1a。

需冻结的设计：选择已验证的身份源或受控账号方案；用户/运营期限、撤销策略、角色核验、密钥来源及轮换。当前无已连接 SSO，不假定可用。

生产缺密钥/开发默认值拒绝启动；新 token 明确到期，校验受众/主体/角色；运营敏感请求核查当前账号状态或权限版本。旧无期限 token/无必要版本字段 token 失效，客户端重新登录并保留待办上下文。退款、黑名单和审计权限不由客户端声明。

验收：T02，禁用/降权/撤销、旧 token、过期和角色不足；日志不输出凭证。回退不重新接受旧无限期凭证。
