# 合规评审：敏感个人信息与高风险产品能力

## 状态

待审批。本文档只定义准入条件，不代表已经允许实现。

适用范围：

- 身份证、强实名、身份证 OCR。
- 实时定位、精确住址、行踪轨迹。
- 通讯录、好友关系、私信。
- 真实用户数据处理。
- 产品定位调整到交友、相亲、约会、脱单、匹配对象等方向。

## 结论

在完成本评审前，不得实现上述能力，不得修改数据库 schema 采集这些字段，不得在测试数据、日志、文档样例或提交历史中出现真实用户数据。

## 必须完成的评审材料

- 个人信息保护影响评估：说明数据类型、处理目的、必要性、处理方式、风险和防护措施。
- 敏感个人信息处理必要性说明：逐项说明为什么普通手机号、问卷、举报和黑名单不足以达成目的。
- 单独同意方案：每类敏感信息必须有单独同意、撤回路径和版本化记录。
- 隐私政策更新：列明收集范围、使用目的、保存期限、共享对象、删除/导出方式。
- 小程序权限说明：实时定位、通讯录、相机/OCR、消息/私信等能力必须有触发场景和拒绝后的替代路径。
- 数据最小化方案：默认不采集，必须说明字段级最小集、脱敏规则、访问角色和日志限制。
- 数据保存与删除：定义保存期限、用户注销/删除请求、导出请求、后台人工处理流程。
- 安全与审计：访问控制、操作审计、日志脱敏、密钥隔离、异常告警。

## 实施准入条件

只有同时满足以下条件，才允许拆分实现任务：

- PRD、PROJECT_CONTEXT、AGENTS 已更新。
- 合规负责人或人工审批人已确认。
- API、数据库、前端、后台和日志的字段级边界已写清。
- 有自动化测试或人工 QA 路径证明未授权用户不能访问敏感信息。
- 有 secret/PII 扫描命令，且扫描通过。

## 明确禁止

- 不得提交真实身份证号、手机号、通讯录、定位、聊天内容、支付记录或举报原文。
- 不得把敏感信息写入前端日志、服务端错误堆栈、测试快照或示例数据。
- 不得以默认勾选、混合授权或不可拒绝授权收集敏感信息。
- 不得在没有删除/导出路径时上线敏感信息采集。

## 参考依据

- 中国网信网《个人信息保护政策法规问答》：个人信息包括身份信息、联系人信息、位置信息、通信信息等；敏感个人信息泄露或非法使用容易导致人格尊严、人身或财产安全受侵害。参考：https://www.cac.gov.cn/2026-01/09/c_1769688003183197.htm
- TC260《网络安全标准实践指南——敏感个人信息识别指南》：行踪轨迹、精准定位、身份证照片等属于敏感个人信息示例。参考：https://www.tc260.org.cn/upload/2024-09-18/1726621097544005928.pdf

本文档不是法律意见；正式上线前需要专项法务、平台规则和隐私合规复核。
