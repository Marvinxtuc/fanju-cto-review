## 0. 与旧稿的根本差异

本稿不再采用“开始前取消一律全退单一服务费”。金额拆为F活动服务费、D履约保证金；M餐费由用户直接付餐厅。普通未成团、普通成团后、晚报名、候补、平台/餐厅取消、履约和申诉分别判定。

**全退D是F+D一笔合并支付中的部分退款。**DR01-01已冻结用户一笔合并支付、后台F/D分项记账和处置；仅退D、F+D全退、D补偿餐厅、PLATFORM_RETAINED及先退D后只补退未退F均须支持。具体渠道部分退款与餐厅结算仍待RV-06，不为沿用旧全额接口改变权益。

本文同步上游已冻结等号及业务机制，保留未覆盖的OP和全部RV；不代签金额配置、举证、结算或法律结论。下方公开正文仍为受限草案；本稿中的结构化矩阵是设计输入，不是授权在现网执行的规则引擎。

## 第一部分：拟向用户展示的退款政策

<a id="rf-v1-01"></a>
### RF-V1-01 适用金额与渠道

饭局由上海闻演信息技术服务有限公司运营。实际收款主体、商户身份及凭证方式尚须【OP-03】核实。付款前分别展示实际活动服务费F、履约保证金D和合计，以一笔F+D支付。F为平台默认价+活动覆盖，活动级优先，默认具体金额未定；D由餐厅逐场提出，经平台批准形成有效版本，须满足D_MIN≤D≤D_MAX。上下限数值未获有权配置及签收前，不启用真实保证金收费。完整支付成功生效时保存价格快照，后续改价不追溯；餐费M到店直接付餐厅，不纳入平台两项退款。

服务费全退指退F，保证金全退指退D，两项全退指退F+D的应退未退部分。额外补偿独立，不以券或平台余额替代应退现金。原则上均原支付渠道原路退回，原渠道客观不能退时进入人工异常处理。

<a id="rf-v1-02"></a>
### RF-V1-02 候补与未成团取消

仍处候补状态时，主动退出一律两项全退；T-24h仍未转正，候补自动结束并产生两项全退义务。每场配置WAITLIST_MAX，未配置或达到上限不创建新候补支付。退出/自动转正竞争按服务端有效事务顺序唯一处理：退出先生效则全退且不得转正；转正先生效则后续按正式报名类别/规则取消。主动退出后合法重入是新申请、新FIFO序号、排队尾。候补不适用时间扣费阶梯；默认人数、资金暴露及重复/未结/到期退款重报交集仍OP-08。

普通未成团用户主动取消按系统可信受理时刻acceptedAt计算Δ=T−acceptedAt：Δ≥24h两项全退；8h≤Δ<24h，F不退、D全退；0<Δ<8h两项不退、D补偿餐厅。恰好24h全退、恰好8h仅退D已由DR02-03冻结，不是暂定。历史曾成团但取消时已失效/重新待成团者按当前实际未成团状态；不能永久按曾成团扣费。不得因后台处理延迟重算Δ或使本应失败全退的订单进入扣费档。

普通最终未成团或早期成团失效至T-24h仍不足最低人数，剩余愿参加用户F+D全退；普通未成团和候补到期本身没有统一额外补偿承诺。

<a id="rf-v1-03"></a>
### RF-V1-03 普通已成团取消与晚报名例外

普通当前有效正式成团后主动取消，F与D均不退。原取消可信受理时Δ>24h，D处置为PLATFORM_RETAINED：业务平台保留、不退用户、不进入该场餐厅补偿，不等同ACCOUNTING_REVENUE；0<Δ≤24h（含恰好24h），D补偿对应餐厅。保证金性质、收入确认、财税和条款有效性仍须RV-01/RV-06，不由本决定代签。

**T-24h至T-8h直接加入有效已成团桌的晚报名用户是明确例外：**Δ≥8h，F不退、D全退，包含恰好8h；0<Δ<8h两项不退，D补偿餐厅，不因桌已成团直接全扣。

T-24h已有效成团的桌在中间窗口失效，继续合法直接补招至T-8h，不恢复候补；达min自动恢复。T-8h仍不足进入餐厅后期低人数决定流程，OP-07/RV-03继续保留，不复活T-24h应失败桌。失效时本人取消按当前未成团阶梯，OP-01/02主体已闭合；恰好T-24h报名分类、失效桌新加入者是否晚报名等未覆盖交集仍OP-05。

<a id="rf-v1-04"></a>
### RF-V1-04 平台/餐厅取消、后期人数和核心变更

平台或餐厅原因取消，无论是否成团，受影响用户F+D全退并有额外补偿，方案由运营决定。补偿必须与退款分开，不能以商家未付款或待商议补偿替代应退款项处理。

T-8h后因其他用户退出跌破最低人数，餐厅不接待，剩余愿参加者两项全退加补偿；原主动退出者仍按本人规则。餐厅愿继续，通知实际人数而不要求再确认，剩余用户仅因人数少退出按本人取消规则；这一特殊规则须OP-07/RV-03审定。

换餐厅必须明确同意；拒绝或动态期限届满未回应，两项全退，原餐厅另有补偿责任。其他核心条件变更不同意也可两项全退；其补偿和超时完整收口尚待OP-09，不自动照搬所有换店细节。

<a id="rf-v1-05"></a>
### RF-V1-05 正常履约、异常与保证金

扫码签到形成到场记录，不等于正常履约已确认。餐厅当晚确认正常后，F保留、D在活动结束次日由平台核对并发起原路退款；漏确认暂不自动退，进入运营待办联系餐厅，不直接判违约。

餐厅可先报异常但无直接扣D权。用户收到异常通知起有48h说明期；首次结果收到后48h内可申请一次异人最终复核。期间不先把争议D结算餐厅。最终维持违约/No-show的D补偿餐厅；翻案按结论原路退D。

48h不回应默认首次违约是已选经营规则，但送达和证据前提尚待OP-13/RV-02；当前不得作为无证据自动扣款。首次违约结果后48h未申请最终复核，自动进入餐厅补偿结算流程，不等于当刻银行到账。

<a id="rf-v1-06"></a>
### RF-V1-06 特殊情况例外

已成团用户因特殊情况无法参加，可凭合理必要证明申请例外。运营获准选择**仅退D**或**F+D全退**；未获批则回到本人原适用规则，保留原取消受理时间。

不自动把疾病、航班取消等统称为已认定不可抗力；材料处理、申请/补证/完成时限须另审，不索取无关完整病史或身份证。履约异常争议与特殊退款是不同流程，不能擅自共用两轮48h。

<a id="rf-v1-07"></a>
### RF-V1-07 申请、审核、批量发起与到账

一般退款申请在系统实际受理后24h内审核；审核通过后的**次日统一批量发起**。客服每日10:00—22:00，但24h审核不是24个客服工作小时；晚读消息不改变受理时刻。

正常履约D退款采用活动结束次日专门批次，不机械增加一轮一般审核。自动成团失败/候补到期退款是否需人工批准、两轮争议如何与一般24h审核衔接、每天批次时刻和异常升级待OP-11。不能为了满足24h而跳过尚未结束的用户48h说明期。

申请受理、审核通过、待批次、已提交渠道、处理中/未知和退款成功是不同进度；实际到账以渠道结果为准，不承诺固定到账时长。合格申请应按规则处理；原渠道客观不能退才走人工异常，不默认以其他支付或券替代。

<a id="rf-v1-08"></a>
### RF-V1-08 异常实收、版本与救济

正式席位待付锁位为10分钟绝对上限，未付/失败/UNKNOWN不计正式成员，到期UNKNOWN也释放席位，资金继续查询/恢复，不直接当失败。释放后晚到完整成功款保留独立实收并建立F+D原路全退义务，不重新抢位或超售；额外重复实收也保留处理义务。未知结果继续查询或人工跟进，不删记录、不当已成功或确定失败。已有应退款项不因餐厅补偿、注销申请或限制名单消失。

保留用户实际确认的全文、版本、金额、时间与活动条件；新规则不追溯降低旧订单权益。平台内部最终复核是内部结论，不排除其他适用救济。当前文本尚未正式批准及设定生效日。

### RF-M08 判定控制与金额守恒（技术设计要求，不新增扣费权）

先核对原资金事实、订单适用政策和已有退款/结算，再识别场景、原因、用户角色、原受理时间和晚报名资格。候补、平台/餐厅取消、核心变更、特殊获批、T-8h后责任分离是明确分支；冲突交集不能用任意统一优先级吞掉，关联OP后返回待政策判定。

F和D必须分项核对原实收、已退、处理中、待处置及最终归属；同一金额不能既退用户又结算餐厅、也不能在等待复核时先确认平台收入。若已退D后又合法应两项全退，只处理尚未退F，不能再退一次D。两项全退不包含M，额外补偿另列。

支付/退款意图与具体渠道流水建立明确关联。恢复、重复任务、回调与查询均需复用可追踪标识并防超额；F+D一笔合并支付的累计退款和处理中金额不超过实际收款，同时按F/D组件分别守恒；本版不再保留两笔支付候选。无收款事实不制造退款，出现额外真实收款也不能因唯一意图约束将其丢掉。

原微信退款文档说明退款可全额或部分原路返回，受理不等于最终成功，详见[sources/REFERENCE_NOTES.md](sources/REFERENCE_NOTES.md)。这是渠道能力参考，不证明饭局已具备对应权限或允许保证金三向处置；实际商户模式与渠道能力须RV-06签收。

### RF-M09 五个不能混同的状态维度

| 维度 | 要独立回答的问题 |
| :--- | :--- |
| 报名资格 | 候补、待付、正式、退出或截止？ |
| 桌位履约 | 待成团、已成团、失效、后期确认、完成或取消？ |
| 资金事实 | 实收是多少、渠道是否成功、F/D分别是什么？ |
| 资金处置 | 应退、审核、待批次、在途未知、已退、待结餐厅或平台业务留存？ |

业务履约“完成”后仍有D待退；不退的决定不等于已付餐厅；身份注销不抹交易事实。不要用一个OrderStatus全包，也不要求机械照本文新增相同枚举。

### RF-O01 人工待办不是任意处置

每个异常有唯一关联事项、原订单/资金标识、政策版本、原因、责任人、下一步及期限；时限未定先登记OP，不填“无限等”。原渠道不可用、余额不足、凭证失效、重试终止等须查明，不通过私下新转账掩盖原退款未知状态。

首次违约复核期内、按期复核中，D暂缓结算；原取消无需争议的D何时结算不能自动套同一48h，应由OP-14明确。维持结论进入餐厅补偿不等于无需核验合法账户和渠道。既有资金安全制度及异人差异复核保留，不以Q88自动进流程删除控制。

### RF-O02 对账与恢复

业务记录查渠道 + 渠道记录反查本地应结合进行，识别本地缺款、额外收款、部分金额退款、D待结/实结和未知退款。账单不可用不能记零差异。恢复备份后核对恢复点前未结项及之后渠道事实，应用有效隐私处置；未收敛前不恢复受影响新收费。

停新收费不停止可信存量回调、查询、退款或履约处置；真实交易不能切Mock来回退。工程方案采用何种任务/锁/索引待当前代码差分及审批，不在本文件直接授权实现。
