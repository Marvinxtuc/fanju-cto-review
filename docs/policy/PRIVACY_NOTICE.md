### PN-V1-04 推荐和内部排桌的边界

时间偏好只用于推荐与开局统计；性别均衡是软目标，不能覆盖餐厅人数与容量、有效报名和付费候补FIFO。平台不提供同桌性别期待，不保证1:1比例，不让性别成为跳过候补队首的理由。多桌策略由餐厅逐场选择平台有限标准策略并留revision；候补退出与转正按服务端有效事务顺序唯一生效，退出后重入取得新队尾序号。保留成团历史不表示永久按曾成团状态确定取消权益；取消用可信acceptedAt及当时实际状态。

实际推荐是否属于需另行说明的自动化决策、拒绝个性化推荐的实现、统计能否用汇总数据等，须在真实实现与处理依据审查中确定。公开版应填入已落实的解释与权利入口，不以本说明承诺尚未建设的控制。

### PN-V1-05 饮食适配、证明材料与第三人信息

首发不提供专门饮食保障。需要超出本场普通菜单范围的保障时，收费前阻止该安排，不要求您改填“无”或接受无条件免责。适配方式以最少信息判断是否可提供服务，不恢复完整健康、宗教或口味问卷。

特殊退款原则上需合理证明，但不默认要求完整病历、诊断、身份证影像或无关第三人资料。证明材料类型、可遮挡字段、受控提交方式、访问范围、保存期与删除方式，须在【OP-10/RV-05】完成后明确告知；在此之前不开放真实敏感材料收集。普通客服和评价文本不是无限收集材料的入口。

用户或餐厅误填无关敏感资料时，平台按经批准流程限制查看和转发，核实必要性并删除/脱敏或另行处理。不把用户一句“同意”作为收取无限材料的依据。任何单独同意或其他处理依据均需按实际用途核实，不由普通AgreementPolicy记录替代。

### PN-V1-08 查询、更正、复制/导出、撤回和注销

用户可以通过【待定：经验证的隐私权利入口】提出请求。首发可以设计受控人工处理，但实际渠道、核验、工具、负责人和期限未经验证前，不宣称已提供一键自动处理。

**用户随时可以申请注销。**如有未结束活动、D、退款、餐厅补偿、申诉或复核，进入注销处理中；相关事项继续，结清后完成注销。注销不删除已发生的资金事实或消灭责任，也不构成无限保留所有画像的理由。

核验以本人账号及关联事项所需最少信息为限，不默认增加身份证或支付密码。查询和导出只包含本人的适用信息，不泄露他人资料或内部安全凭证。修改当前时间偏好等不回写过去报名条件和已完成资金决定。

注销处理中是否允许新报名、可否撤销注销、最终期限及各终态访问范围尚待OP-15确认。不能仅因提出注销就擅自取消饭局并扣D。对只能部分完成的请求应说明范围、原因和后续安排；其他适用救济不因平台内部流程终结而排除。

### PN-V1-09 通知、时钟与信息安全

履约异常首次说明期和最终复核申请期，均从用户收到相应通知起计算48小时。实际送达依据与失败处理须先审定；不能仅因后台生成消息就记为已收到并扣D。在线客服已确定的时段不等于所有通知都能到达，也不代表已启用订阅消息、短信或电话。

正式发布时仅列实际通过验收的传输、存储、权限、日志、备份及应急措施【待定：真实环境证据】。不使用“永不泄露”“全部数据绝对安全”等无法证明的表述。发生相关信息安全问题时，通过经核实的应急方案处置并履行相应告知职责。

### PN-V1-10 版本、生效与用途变化

本说明的正式版本、生效时间、批准记录及与用户协议/退款政策的关联为【待定：发布清单】。新资料类别和用途需要重新评审并作适用告知；不因旧用户已经勾过一个总协议，就认为新的性别必填、证明材料或分享均已授权。

政策发布包用于还原全文、版本和用户实际确认；不能替代依法应单独满足的处理依据或同意要求。历史文本和订单证据不被新版本静默覆盖。V1.1仅同步15项获批业务决定，不改变尚未获批的资料类别、留存期限、餐厅共享和权利入口；政策束仍为草案，不能借V1.0的WP10-A或旧Gate启用。

## 第二部分：给实施团队的内部落地要求

### PN-I-V1-01 字段迁移不做破坏性删除

对当前Schema、接口入参/响应、前端表单、验证函数、日志、历史快照及备份逐处盘点。`preferredAreas`、`budgetRange`、`tableVibe`、`tastePreferences`和个人`acceptableTableSizes`等仅是清单/历史实现中需查找的名字，不宣称最新代码仍全部存在。

目标是停止新采集与新必填约束，并兼容历史；具体弃用、回填和删除分阶段设计，不能直接drop历史列。原`dietaryRestrictions`等即使准备停用，也不能一并删除“收费前服务适配”要求。该要求应以批准的最小新流程替代，而不是恢复完整饮食问卷。

### PN-I-V1-02 权利请求最小人工闭环（候选设计，非已提供功能）

| 步骤 | 必须实现的结果 | 证据 |
| :--- | :--- | :--- |
| 受理 | 可用入口收件，关联本人，记录首次请求时间和范围 | 请求ID、渠道、时间，不输出敏感值到Git |
| 核验 | 最小必要确认账号归属，不增加无关身份证 | 核验方法、结论、授权人员 |
| 盘点 | 区分可处理资料、待结资金/履约、必须保留事实 | 按R01—R12分项，不整号笼统冻结 |
| 执行 | 使用获批受控工具完成更正、导出、最小化/删除 | 动作和范围审计，非裸SQL私下改库 |
| 复核 | 校验无他人信息泄露、必要资金义务仍可追踪 | 复核人及结果，不能假装已演练 |
| 回复 | 安全交付本人，说明部分保留、后续期限和复核渠道 | 非公开永久链接的受控交付记录 |
| 后续 | 未结事项处理完成后推动注销；到期清理与备份恢复再应用处置 | 有主责及异常待办，不无限搁置 |

### PN-I-V1-03 材料与餐厅最小权限

证明附件单独受控，不随审计metadata、通知正文或导出全表传播。餐厅逐人确认可采用最小内部标识等候选方式，但没有批准具体字段；必须能防跨餐厅、跨活动、他人订单确认。扫码防重放/代签是设计工作，不引入人脸/GPS作为默认解决方案。

### PN-I-V1-04 专项审查与发布

对性别必填是否属于服务所必需、自动决策的适用要求、敏感证明、餐厅共享和留存/注销进行明确签收，关联RV-04/RV-05及OP-10/13/15。相关法律核对范围见[sources/REFERENCE_NOTES.md](sources/REFERENCE_NOTES.md)，不能通过一个总勾选回避处理依据，也不能由Codex自行变更业务政策。
